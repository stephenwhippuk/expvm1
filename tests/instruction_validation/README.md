# Instruction Validation Test Suite

## Purpose

This test suite provides **comprehensive validation** of every instruction in the Pendragon Virtual Machine instruction set. These tests are designed to systematically verify correct behavior and catch implementation issues that previous ad-hoc testing missed.

## Design Principles

1. **Complete Coverage**: Every instruction (0x00-0x76, 0x7F) has dedicated tests
2. **Isolated Testing**: Each test focuses on specific instruction behavior
3. **Documented Expectations**: Every test file documents expected register/memory states
4. **Systematic Organization**: Tests grouped by instruction category for maintainability
5. **Edge Case Focus**: Special attention to boundary conditions and corner cases

## Test Structure

Tests are organized as:
- **Binary test files** - Generated by `generate_test_binaries.py` in `binaries/` directory
- **Test scripts** - Python-based test runner using the binary generator
- **Documentation** - Test coverage tracking in COVERAGE.md and TEST_SUMMARY.md

## Test Categories

### Core Operations
- **Control Flow** - NOP (0x00), HALT (0x01)
- **Register Operations** - LD, LDH, LDL, SWP (0x02-0x08)
- **Memory Operations** - LDA, LDAB, LDAH, LDAL variants (0x09-0x0F, 0x72-0x74)
- **Stack Operations** - PUSH, POP, PEEK, FLSH variants (0x10-0x1A, 0x75-0x76)
- **Memory Paging** - PAGE instructions (0x1B-0x1C)
- **Jump Instructions** - JMP, JPZ, JPNZ, JPC, etc. (0x1E-0x26)
- **Subroutines** - CALL, RET, SETF (0x1D, 0x27-0x28)

### Arithmetic Operations
- **Addition** - ADD, ADB, ADH, ADL (0x29-0x2D)
- **Subtraction** - SUB, SBB, SBH, SBL (0x2E-0x32)
- **Multiplication** - MUL, MLB, MLH, MLL (0x33-0x37)
- **Division** - DIV, DVB, DVH, DVL (0x38-0x3C)
- **Remainder** - REM, RMB, RMH, RML (0x3D-0x41)

### Logical Operations
- **AND** - AND, ANB, ANH, ANL (0x42-0x46)
- **OR** - OR, ORB, ORH, ORL (0x47-0x4B)
- **XOR** - XOR, XOB, XOH, XOL (0x4C-0x50)
- **NOT** - NOT, NOTB, NOTH, NOTL (0x51-0x55)

### Bit Manipulation
- **Shift Left** - SHL, SLB, SLH, SLL (0x56-0x5A)
- **Shift Right** - SHR, SHRB, SHRH, SHRL (0x5B-0x5F)
- **Rotate Left** - ROL, ROLB, ROLH, ROLL (0x60-0x64)
- **Rotate Right** - ROR, RORB, RORH, RORL (0x65-0x69)

### Other Operations
- **Increment/Decrement** - INC, DEC (0x6A-0x6B)
- **Comparison** - CMP, CPH, CPL variants (0x6C-0x71)
- **System Calls** - SYS (0x7F)

## Running Tests

### Full Suite
```bash
# Run entire validation suite
cd tests/instruction_validation
./run_all_tests.sh
```

### Individual Test Binary
```bash
# Generate test binaries
python3 generate_test_binaries.py

# Run specific binary
./build/lvm binaries/test_001_nop.bin 0x0000

# Verify results (register dump, memory inspection, etc.)
```

## Test File Format

Each test file follows this structure:

```assembly
; Test: <Test Name>
; Instruction: <Mnemonic> (0x<HEX>)
; Purpose: <What this test validates>
;
; Expected Results:
;   AX = 0x<value>
;   BX = 0x<value>
;   Flags: ZERO=<0/1>, CARRY=<0/1>, SIGN=<0/1>, OVERFLOW=<0/1>
;   Memory[0x<addr>] = 0x<value>
;
; Test Description:
;   <Detailed description of test scenario>

<assembly code>

HALT
```

## Test Development Process

### Adding New Tests
1. Create test file in appropriate category folder
2. Document expected results in file header
3. Implement test logic
4. Add to category test runner
5. Verify test passes/fails as expected

### Test Verification
Tests should verify:
- ✓ Register values after execution
- ✓ Flag states (ZERO, CARRY, SIGN, OVERFLOW)
- ✓ Memory contents (for load/store operations)
- ✓ Stack state (for stack operations)
- ✓ Program counter (for jump operations)

## Flag Behavior Reference

| Flag | Set When |
|------|----------|
| ZERO | Result equals zero |
| CARRY | Arithmetic carry/borrow or bit shifted out |
| SIGN | Result has bit 15 set (negative in two's complement) |
| OVERFLOW | Signed arithmetic overflow |

## Common Test Patterns

### Testing Flag Setting
```assembly
LD AX, 0x0000       ; Clear AX
ADD 0x0001          ; Simple addition
; Expected: AX=0x0001, ZERO=0, CARRY=0
HALT
```

### Testing Register Independence
```assembly
LD AX, 0x1234
LD BX, 0x5678
LD CX, 0xABCD
; Verify AX, BX, CX maintain values
HALT
```

### Testing Memory Operations
```assembly
LD AX, 0x1234
LDA 0x1000, AX      ; Store to memory
LD AX, 0x0000       ; Clear AX
LDA AX, 0x1000      ; Load from memory
; Expected: AX=0x1234
HALT
```

## Test Coverage Goals

- [ ] All 119 instructions tested individually
- [ ] All instruction variants tested (immediate, register, byte, word)
- [ ] All flags tested in relevant contexts
- [ ] All registers tested as operands
- [ ] Edge cases (0, max, overflow, underflow)
- [ ] Boundary conditions (memory limits, stack limits)
- [ ] Instruction combinations (flag-dependent jumps, etc.)

## Test Results Tracking

Test results should be tracked in:
- **RESULTS.md** - Overall test pass/fail summary
- **ISSUES.md** - Documented bugs found by tests
- **COVERAGE.md** - Coverage matrix showing tested instructions

## Notes for Test Authors

1. **Keep tests atomic** - One behavior per test file
2. **Document thoroughly** - Expected results must be explicit
3. **Use meaningful names** - `test_add_overflow.asm` not `test1.asm`
4. **Test edge cases** - Zero, max, min, overflow, underflow
5. **Verify side effects** - Check unaffected registers/memory
6. **Consider endianness** - Remember little-endian byte order
7. **Test flag interactions** - Some operations preserve flags
