# Quick Start Guide - Instruction Validation Tests

## Getting Started

### Prerequisites
1. Build the project:
   ```bash
   cd /home/stephen/localdev/experiments/vms/expvm1
   cmake -B build -DCMAKE_BUILD_TYPE=Debug
   cmake --build build
   ```

2. Verify binaries exist:
   - `build/lvm` - Virtual machine
   - `build/asm` - Assembler

### Running Tests

#### Run All Tests
```bash
cd tests/instruction_validation
./run_all_tests.sh
```

#### Run Single Test
```bash
# Generate test binaries (if not already generated)
python3 generate_test_binaries.py

# Run specific test
./build/lvm binaries/test_001_nop.bin 0x0000
```

## Writing a Test

### Basic Test Template

```assembly
; Test: [Descriptive Name]
; Instruction: [MNEMONIC] (0x[HEX])
; Purpose: [What this validates]
;
; Expected Results:
;   AX = 0x[value]
;   BX = 0x[value]
;   CX = 0x[value]
;   DX = 0x[value]
;   EX = 0x[value]
;   Flags: ZERO=[0/1], CARRY=[0/1], SIGN=[0/1], OVERFLOW=[0/1]
;   Memory[0x[addr]] = 0x[value]  ; if testing memory
;   Stack Pointer = 0x[value]      ; if testing stack
;
; Test Description:
;   [Detailed explanation of what the test does and why]

; Setup phase
LD AX, 0x0000           ; Initialize registers to known state
LD BX, 0x0000
LD CX, 0x0000

; Test execution
[instruction under test]

; Verification (optional - can inspect after HALT)
; Put results in predictable places for inspection

HALT
```

### Example Tests

#### Simple Instruction Test
```assembly
; Test: Basic HALT
; Instruction: HALT (0x01)
; Purpose: Verify HALT stops execution
;
; Expected Results:
;   VM exits with code 0
;   All registers maintain their values

LD AX, 0x1234
LD BX, 0x5678
HALT
; Execution should never reach here
LD CX, 0xFFFF  ; This should not execute
```

#### Arithmetic Test
```assembly
; Test: ADD Basic
; Instruction: ADD (0x29)
; Purpose: Verify simple addition
;
; Expected Results:
;   AX = 0x0005
;   ZERO = 0, CARRY = 0, SIGN = 0, OVERFLOW = 0

LD AX, 0x0002
ADD 0x0003
; Result: AX should be 0x0005
HALT
```

#### Flag Test
```assembly
; Test: ADD Overflow
; Instruction: ADD (0x29)
; Purpose: Verify CARRY flag set on overflow
;
; Expected Results:
;   AX = 0x0000
;   ZERO = 1, CARRY = 1

LD AX, 0xFFFF
ADD 0x0001
; Result: AX = 0x0000, CARRY = 1, ZERO = 1
HALT
```

#### Memory Test
```assembly
; Test: LDA Store/Load Roundtrip
; Instruction: LDA (0x09, 0x0D)
; Purpose: Verify store and load preserve value
;
; Expected Results:
;   AX = 0xABCD
;   Memory[0x1000] = 0xABCD (little endian: CD AB)

LD AX, 0xABCD
LDA 0x1000, AX      ; Store AX to memory
LD AX, 0x0000       ; Clear AX
LDA AX, 0x1000      ; Load from memory
; Result: AX should be 0xABCD
HALT
```

## Test Organization

### File Naming Convention
- `test_[instruction]_[variant]_[purpose].asm`
- Examples:
  - `test_add_basic.asm`
  - `test_add_overflow.asm`
  - `test_ld_all_registers.asm`
  - `test_cmp_signed_vs_unsigned.asm`

### Category Structure
Tests are now generated as numbered binaries in the `binaries/` directory:
```
binaries/
    test_001_nop.bin           - NOP instruction test
    test_002_halt.bin          - HALT instruction test
    test_003_ld_ax.bin         - LD to AX register test
    ...
    test_118_sys.bin           - System call test
```

Tests are generated by `generate_test_binaries.py` using the `InstructionEncoder` class.

## Verification Methods

### Manual Verification
After running a test, check:
1. Exit code (0 = success)
2. Register dump (if VM provides)
3. Memory dump (for load/store tests)

## Common Patterns

### Testing All Registers
```assembly
; Test each register
LD AX, 0x1111
LD BX, 0x2222
LD CX, 0x3333
LD DX, 0x4444
LD EX, 0x5555
; Verify all maintain values
HALT
```

### Testing Flag States
```assembly
; Setup condition for flag
LD AX, 0x0000
ADD 0x0000
; ZERO flag should be set
HALT
```

### Testing Byte Operations
```assembly
; Test high/low byte independence
LD AX, 0x1234
LDH AX, 0xAB        ; Load high byte
; AX should be 0xAB34
LDL AX, 0xCD        ; Load low byte
; AX should be 0xABCD
HALT
```

## Debugging Tips

### VM Output
The VM may provide debug output showing:
- Register states after execution
- Memory contents
- Flag states
- Stack contents

### Test Isolation
If a test fails:
1. Simplify to minimal case
2. Remove unrelated instructions
3. Verify expected behavior against spec
4. Check if it's a test bug or VM bug

### Comparison with Spec
Always refer to `/specification/PendragonOperations.md` for:
- Exact instruction behavior
- Argument types and order
- Flag setting rules
- Side effects
